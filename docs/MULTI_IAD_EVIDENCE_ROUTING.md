# 多 IAD「证据路由」方案：先路由，后采信

> 版本：v0.1（设计稿 / 未实现）
> 前置文档：`MULTI_IAD_ANOMALY_MAP_FUSION.md`（v1「自适应异常图融合」）
> **本文改变 v1 的一个核心假设**：不再要求所有专家在**像素级**共同投票，
> 改为「每个专家独立出证据 → 路由器判断该采信谁 → 用主专家的 map 输出」。
> 基线仍以 `D:\triad\labelingcopilot_my\annotate` 为准；本文只做设计与实验规划，不含代码改动。

---

## 0. TL;DR

- **弃用「硬融合」作为默认路径**。`mean` / `product` 都隐含"两个专家在同一像素上有同义、同可靠度的证据"，
  这个假设在异构 IAD（结构型 MuSc、语义型 AnomalyCLIP、逻辑型待接入）上不成立。
- **改为证据路由**：所有专家都跑，每个专家出一张 **evidence card**（分数/面积/连通域/熵/一致性/稳定性），
  路由器据此判断"当前这种证据模式该信任谁"，输出**一个主专家**（可带一个辅助专家做确认），
  最终 map **直接取自主专家**，不与其他专家的 map 做像素平均。
- 这把"判断任务类型"从**显式分类问题**（这是 bent_wire 还是 cable_swap？）
  转成**隐式的证据加权/选择问题**（这种证据模式下，哪个专家更可靠？）。
- 路由层的判据必须是 **GT-free**（标定集学到的可靠性 + 专家间分歧 + 不确定性 + 规格先验），推理时冻结。
- 路由的三个必要条件：**① 分数可跨专家比较（逐专家校准）② 支持弃权/复核 ③ 有一个真正擅长该模式的专家存在**。
  第三条是本文最大的开放问题：**逻辑型缺陷目前没有真正的逻辑专家可路由**。

## 1. 动机：实测证据（为什么不再硬融合）

### 1.1 两版结果（cable，150 张 = 58 good + 92 defect）

| 指标 | 旧基线（product + batch p2/p98） | 实验配置（逐专家冻结校准 + mean） |
|---|---|---|
| pixel AUROC | 0.7991 | **0.8727** |
| image AUROC（legacy max） | 0.7186 | **0.8473** |
| image AUROC（top-0.5% 均值） | — | **0.8984** |
| 饱和分数（max==1.0） | 60/150 | **0/150** |
| 缺陷 IoU 均值 | **0.127** | **0.076** |
| IoU == 0 的缺陷数 | **21/92** | **45/92** |

> ⚠️ **口径说明（重要）**：实验配置那一列是在「关闭 MeBin 腐蚀 + 面积过滤 + 冻结阈值区间 `[97,255]`」下跑出来的，
> 而该 MeBin 改动事后被判定为错误方向，已回退。因此：
> - **AUROC 两项可信**（pixel AUROC 只用 map，不用 mask）；
> - **IoU 两项不可用于结论**，必须在 MeBin 恢复默认后重跑；
> - 但 §1.2 的 per-type 形态差异是可复现的结构性现象，值得作为设计依据。

### 1.2 per-type IoU：融合不是"整体变差"，而是"有的类变好、有的类变差"

| 缺陷类型 | 缺陷族 | 旧基线 meanIoU | 实验配置 meanIoU | 方向 |
|---|---|---|---|---|
| bent_wire | 结构 | 0.290 | 0.084 | **显著变差** |
| poke_insulation | 结构 | 0.225 | 0.175 | 变差 |
| cut_outer_insulation | 结构 | 0.195 | 0.224 | 变好 |
| combined | 混合 | 0.129 | 0.084 | 变差 |
| cut_inner_insulation | 结构 | 0.107 | 0.050 | 变差 |
| missing_wire | 逻辑 | 0.057 | 0.020 | 变差 |
| missing_cable | 逻辑 | 0.010 | 0.000 | 持平（本就全灭） |
| cable_swap | 逻辑 | 0.005 | 0.004 | 持平（本就全灭） |

### 1.3 结论：**排序（ranking）可融合，定位（localization）不可融合**

- 连续 anomaly map 的**排序能力**确实提升了（pixel AUROC +0.074，且饱和并列消失）。这类信息是"图像级/区域级"的，
  多专家取平均是合理的。
- 但**像素级定位**的可靠性是**逐专家、逐缺陷族**不同的：
  - 同一张 `bent_wire`，MuSc 的峰值可能正确，AnomalyCLIP 的峰在别处；平均后峰值对比度被稀释，二值化就吞掉了。
  - 反过来 `cut_outer_insulation` 上 AnomalyCLIP 的语义证据更有用。
  - `missing_cable` / `cable_swap` 这类**逻辑型**缺陷，两家都不擅长，平均只是把两个不擅长它的模型混合起来。
- 因此正确的动作不是"重新调融合权重"，而是**"先判断该信谁，再采信它的图"**。

## 2. 核心思路

### 2.1 一句话

> 专家先独立完成判断；路由器只判断"当前证据模式下谁更值得信任"；
> 最终输出**优先采信一个主专家**，而不是把不兼容的 map 强行平均。

### 2.2 流程

```
            ┌────────────── 专家库（全部独立跑）──────────────┐
            │ E_struct(MuSc)   E_semantic(AnomalyCLIP)   E_logic │
            └───────┬───────────────┬────────────────────┬──────┘
                    │ M_k, s_k      │                    │
                    ▼               ▼                    ▼
            ┌──────────────── 逐专家校准（L0）────────────────┐
            │  raw map → 单调归一化；raw score → 校准置信度     │
            └───────────────────────┬───────────────────────┘
                                    ▼
            ┌──────────── Evidence Card（见 §4）────────────┐
            │ 各专家峰值/面积/连通域/熵/稳定性 + 两两分歧    │
            └───────────────────────┬───────────────────────┘
                                    ▼
            ┌──────────── Router（见 §5）──────────────────┐
            │ 输出 {primary, secondary?, confidence,      │
            │       reason_code, action}                  │
            └───────────────────────┬───────────────────────┘
                                    ▼
            ┌──────── 采信（见 §7）───────────────────────┐
            │ action=use_primary → 直接用主专家 map        │
            │ action=confirm     → 辅专家做 ROI 确认       │
            │ action=review      → 弃权/复核（见 §6）      │
            └───────────────────────┬───────────────────────┘
                                    ▼
                          逐主专家 MeBin（见 §8）→ mask
```

### 2.3 与 v1 的关系

| v1 组件 | 本文处置 |
|---|---|
| L0 逐专家归一化/校准 | **保留**（且是路由的前提：分数必须可跨专家比较） |
| L1 图像级门控 \(g_k\) | **升级为路由器**（从"连续权重"变成"选主专家 + 可选辅专家"） |
| L3 像素级融合算子 | **降级为可选/消融项**，不再作为默认路径 |
| L4 MeBin | **改为逐专家配置**（不同专家的 map 分布不同，不能共用一套阈值逻辑） |
| 级联调度（L2） | 保留（但路由正确性优先于成本） |

## 3. 形式化

设 K 个专家 \(\{E_k\}\)，对图 \(x\) 输出 map \(M_k(x)\) 与图像级分数 \(s_k(x)\)。

引入逐专家校准函数 \(\phi_k\)（标定集学到、推理冻结），得：

\[
\tilde s_k(x)=\phi_k(s_k(x))\in[0,1],\qquad \tilde M_k(x)=\psi_k(M_k(x))
\]

证据卡：

\[
e(x)=\big[\{\tilde s_k, a_k, c_k, H_k, \sigma_k\}_{k=1..K},\ \{d_{ij}\}_{i<j},\ \text{ctx}\big]
\]

其中 \(a_k\)=异常面积比，\(c_k\)=最大连通域比，\(H_k\)=map 熵，\(\sigma_k\)=TTA 稳定性，\(d_{ij}\)=两两分歧，ctx=类别/规格等已知上下文。

路由器：

\[
r(x)=\pi(e(x))\in\{1..K\}\cup\{\text{review}\}
\]

最终：

\[
F(x)=\begin{cases}M_{r(x)}(x), & r(x)\in\{1..K\}\\ \varnothing\ (\text{待复核}), & r(x)=\text{review}\end{cases}
\]

**学习目标（关键）**：\(\pi\) 学的不是 \(P(\text{defect type}\mid x)\)，而是

\[
P\big(k=\arg\max_{j}\ \text{quality}(M_j(x))\ \big|\ e(x)\big)
\]

即"在这种证据模式下，哪个专家的输出更接近正确答案"。这是 **reliability router**，不是分类器。

## 4. Evidence Card（证据卡）

路由质量几乎完全取决于证据卡。**只看一个 `score` 一定不够**。

### 4.1 每个专家输出

| 字段 | 含义 | 为什么要它 |
|---|---|---|
| `score_max` | map 最大值 | 便宜，但最易被单像素顶穿（仅作参考） |
| `score_topk` | top-0.5% 像素均值 | **主证据**：抗单点、仍是空间证据 |
| `anom_area` | 阈值化后前景占比 | 区分"孤立尖点"与"成片异常" |
| `largest_comp` | 最大连通域面积 / 前景面积 | 区分零散噪声与连续缺陷 |
| `n_comp` | 连通域个数 | 计数型异常（缺件/多件）的线索 |
| `entropy` | map 归一化后熵 | 低熵=集中异常；高熵=弥散/不确定 |
| `peakedness` | \((\text{mean}/\text{max})\) 或峰度 | 单峰 vs 弥散 |
| `tta_std` | TTA（翻转/多尺度）后 topk 标准差 | **不确定性**：不稳定就别信它 |
| `border_mass` | 靠边前景占比 | 误报常来自背景/取景边缘 |

### 4.2 专家间关系

| 字段 | 含义 | 用途 |
|---|---|---|
| \(d^{score}_{ij}\) | 校准后分数差 | 主判据（例：logic 高 + struct 低 → 逻辑模式） |
| \(d^{area}_{ij}\) | 异常面积差 | 判断"谁在图里看到了成片的东西" |
| \(\rho^{rank}_{ij}\) | 两张 map 的 Spearman 相关 | 高分区域是否一致 |
| \(\text{IoU}_{ij}@\tau\) | 高分区域重叠度 | 一致 → 可互相确认；冲突 → 需要复核 |

### 4.3 上下文

- 类别/工位/物料（若已知）；
- **规格先验**：该类是否有"必须存在的部件清单"（决定逻辑专家是否适用）；
- 成本预算（决定级联，见 §5.4）。

### 4.4 示例

```json
{
  "image": "cable/test/cable_swap/003.png",
  "ctx": {"category": "cable", "has_spec": true},
  "experts": {
    "MuSc":         {"score_topk": 0.18, "anom_area": 0.004, "largest_comp": 0.31,
                     "n_comp": 3, "entropy": 6.9, "peakedness": 0.42, "tta_std": 0.05},
    "AnomalyCLIP":  {"score_topk": 0.24, "anom_area": 0.011, "largest_comp": 0.22,
                     "n_comp": 5, "entropy": 7.2, "peakedness": 0.35, "tta_std": 0.09},
    "LogicExpert":  {"score_topk": 0.91, "anom_area": 0.030, "largest_comp": 0.68,
                     "n_comp": 1, "entropy": 3.1, "peakedness": 0.55, "tta_std": 0.02}
  },
  "pairwise": {"MuSc|AnomalyCLIP": {"d_score": 0.06, "rho": 0.21},
               "MuSc|LogicExpert":  {"d_score": 0.73, "rho": 0.08}},
  "route": {"primary": "LogicExpert", "secondary": null,
            "confidence": 0.87, "reason_code": "logic_high_struct_low", "action": "use_primary"}
}
```

## 5. 路由器三档实现

### 5.1 档 A：规则路由（零训练，先跑通）

按"证据模式"写显式规则，**优先级从高到低**：

| 条件 | 动作 | reason_code |
|---|---|---|
| 仅某专家 \(\tilde s\ge\tau_{hi}\) 且其余 \(\le\tau_{lo}\) | 选它 | `single_expert_high` |
| 逻辑专家高、结构专家低 | 选逻辑专家 | `logic_high_struct_low` |
| 结构专家高、逻辑专家低 | 选结构专家 | `struct_high_logic_low` |
| 多专家都高且 \(\text{IoU}_{ij}\) 高（互相确认） | 选 `score_topk` 最高者 | `agreement` |
| 多专家都高但 \(\text{IoU}_{ij}\) 低（空间冲突） | review | `spatial_conflict` |
| 全部低 | review（可能是漏检） | `all_low` |
| 最高 \(\tilde s\) 与次高差 \(<\delta\) | review | `ambiguous` |

要点：

- 阈值 \(\tau\) 用**标定集**调，不用测试集；
- 每条规则都能落成结构化配置，可审计、可复现；
- 这是**第一个该做的实验**：不学任何东西就能验证"选对专家"是否比"平均"好。

### 5.2 档 B：学习型 reliability router

- 模型：logistic regression / GBM / 小 MLP（**先别上深模型**）。
- 输入：§4 的 evidence card（标准化后）。
- 输出：K+1 类（各专家 + review）。
- 标签（关键，**不是缺陷类型**）：在 **train/val** 分片上，对每张图算
  \(\arg\max_k \text{IoU}(M_k, \text{GT})\)（或 per-image AUROC 代理），即 **oracle expert**。
- 训练目标：最小化路由决策与 oracle 的不一致（可加类别平衡，避免多数专家主导）。
- 报告必带 **router accuracy vs oracle**，以及 **oracle 上界**（见 §10）。

### 5.3 档 C：允许"辅助专家"

主专家一旦确定，**辅助专家只做有限动作**（不得再对主 map 做全图平均）：

1. **置信度修正**：主高 + 辅支持 → 提权；主高 + 辅反对 → 降权/复核。
2. **ROI 内确认**：只在主专家的候选区域内看辅助证据，不扩展到全图。
3. **局部补洞**：仅在主 map 的低置信连通域上，用辅 map 做有条件填充。

### 5.4 成本：级联（可选，晚于正确性）

便宜专家先跑 → 算分歧/不确定性 → 共识高则直接输出；灰区才调贵专家（逻辑专家/检测器）。
**注意**：级联不能与"路由正确性"同时优化，否则无法归因；先把"全跑 + 选对"做对，再谈省。

## 6. 弃权 / 复核（必须有）

路由**不允许每次强行选一个专家**，否则"没有可靠证据"会被误判成"某专家最可靠"。

必须支持 `review`：

- 全部专家低分；
- 最高与次高过近（ambiguous）；
- 分数高但空间冲突（spatial_conflict）；
- 主专家 TTA 不稳定（`tta_std` 高）；
- 主专家高分区域贴边 / 弥散（`border_mass` 高、`largest_comp` 低）。

弃权率是**一等指标**（见 §10），不能只报"选了之后的效果"。

---

## 7. 采信规则（为什么不平均）

若 `action = use_primary`：

\[
F(x) = \tilde M_{p}(x),\qquad p=\text{primary}
\]

- **不做跨专家像素平均**：平均会稀释主专家的峰值对比度，这正是 §1.3 观察到的"排序变好、定位变差"。
- 若确需用两家信息而主专家可信，只允许 §5.3 的三种受限动作。
- 跨专家**信息合并**应发生在**图像级**（分数、决策），而不是**像素级**。

## 8. 与 MeBin 解耦（路由方案的额外收益）

不同专家的异常图分布差异极大。**实测（cable 标定集，36 张）**：

| 专家 | 原始 map 量程 | p1 | p99 |
|---|---|---|---|
| MuSc | 相似度类，窄 | 0.0508 | 0.657 |
| AnomalyCLIP | **4 层特征图相加**，宽 | 0.00265 | **2.293** |

> 工程事实：AnomalyCLIP 的 map 是 `torch.stack(4 层 anomaly_map).sum(0)`，
> 量程约 `[0, ~4]`，**不在 [0,1]**。任何"它已经是概率"的假设都是错的。

后果：

- 硬融合后把一张混合分布的图送进**同一个** MeBin，`search_range` / 稳定平台假设都可能失配
  （实测：冻结区间取了另一类别的 `[97,255]`，cable 上阈值被压在 98–126，落在背景与峰值重叠带）。
- **路由方案天然规避这一点**：每个专家保留自己的分布，各自一份 MeBin 配置：

```jsonc
{
  "experts": {
    "MuSc":         { "mebin": { "sample_rate": 4, "min_interval_len": 2, "erode": true } },
    "AnomalyCLIP":  { "mebin": { ... } },
    "LogicExpert":  { "mebin": { ... } }
  }
}
```

- **前提**：MeBin 的功能不要改（6×6 腐蚀是算法的一部分——关掉腐蚀会破坏"连通域数量稳定序列"，
  实测导致 `get_threshold` 大面积回落到 255、输出空 mask）。只允许**传参**，不允许改算法。

## 9. 为什么这比硬融合更适合异构专家

| 维度 | 硬融合（mean/product） | 证据路由 |
|---|---|---|
| 对专家的假设 | 同义、同可靠度、像素级可比 | 只需"各有所长"，不需同义 |
| 单专家优势 | 被另一专家稀释/否决 | 主专家完整保留 |
| 可解释性 | 权重是数字 | `reason_code` + 证据卡可审计 |
| MeBin 适配 | 一张混合分布图，难配 | 逐专家配置 |
| 失效模式 | 默默变差（看不出为什么） | 可弃权，可定位是"没专家"还是"路由错" |
| 新增专家的代价 | 需重新调权重/标定 | 只需登记到证据卡与规则 |

## 10. 评测协议

### 10.1 必比方案

| 名称 | 说明 |
|---|---|
| `S_k` best-single | 每个专家单独跑（含"每类各自最佳单专家"） |
| `F_mean` | 校准后等权平均 |
| `F_rankmean` | rank 后平均（零训练强基线） |
| `F_max` | 逐像素取最大 |
| `F_product` | 原基线（失败项，保留对照） |
| `R_max` | **按原始分数投票**（最弱路由，用来证明"校准"必要） |
| `R_rule` | 档 A 规则路由 |
| `R_learn` | 档 B 学习路由 |
| `R_oracle` | **GT 事后选最优专家（上界，只作参照，不作结果）** |

### 10.2 关键诊断顺序

1. `R_oracle` **是否显著高于 best-single？**
   - 若否 → **专家之间互补性不足**，路由无意义，直接做 best-single。
2. `R_learn` 与 `R_oracle` 的差距：
   - 差距大 → 问题在路由器（证据卡不够 / 标签不对 / 样本太少），不在专家。
3. `R_learn` vs `F_mean`：
   - 若 `R_learn` 不超过 `F_mean`，说明"平均"已经在做隐式路由，路由没有额外收益。
4. `R_max` vs `R_learn`：
   - 差距 = 校准与证据卡的贡献。

### 10.3 必报指标

- **效果**：pixel AUROC、image AUROC（top-k 分数，不用 `max`）、缺陷 IoU 均值/中位、per-type IoU。
- **路由**：
  - `router accuracy`（与 oracle expert 的一致率）；
  - **各专家被选中的频率**（是否退化成"永远选某一个"）；
  - **弃权率**与弃权样本的真实异常率；
  - **错误路由的代价**（选错专家时 IoU 掉多少）。
- **假阳性**：good 图的前景像素占比分布（`fg>1000 / >5000 px` 计数）。
- **成本**：专家调用次数、平均延迟（级联时）。

### 10.4 成功判据（诚实设定）

- `R_rule` 已不低于 best-single，且在**混合分布**上优于 `F_mean`；
- 在专家专长类上**不劣化**（例：`bent_wire` 不因引入逻辑专家而掉点）；
- 弃权率可接受（业务上可复核），且弃权样本确实是低置信；
- 路由结果可解释（`reason_code` 分布合理，不是单一规则吃掉全部样本）。

## 11. 里程碑

- **R0｜先把单专家基线做干净**（前置，不做路由）
  - MeBin 恢复默认（腐蚀开、不改算法）；逐专家单独跑完整 cable，产出 per-expert / per-type 表。
  - **产出**：`S_k` 的干净数字。没有它，路由的价值无法判断。
- **R1｜证据卡 + 规则路由（零训练）**
  - 实现 §4 的指标与 §5.1 的规则；对比 `S_k` / `F_mean` / `R_rule` / `R_oracle`。
  - **决策点**：`R_oracle` 是否显著 > best-single。**若否，停止该路线。**
- **R2｜校准 + 学习型路由**
  - 逐专家分数校准 → 小模型 reliability router；严格 train/val/test；报 router accuracy 与弃权率。
- **R3｜主专家 + 辅助专家确认**
  - 只在低置信/空间冲突时启用辅专家（ROI 确认 / 置信修正）。
- **R4｜接入真正的逻辑专家 + 级联**
  - 这是**逻辑型缺陷（missing_cable / cable_swap）唯一可能的解**：必须有能表达"部件存在性/位置/拓扑"的专家；
    否则路由只能在两个不擅长的专家之间挑，收益为零。

## 13. 风险与开放问题

| # | 风险 | 说明 / 缓解 |
|---|---|---|
| 1 | **专家分数不可比** | 必须先做逐专家校准（\(\phi_k\)），否则"取最大"退化成"谁背景高选谁"。`R_max` 就是用来暴露这个问题的对照。 |
| 2 | **没有真正的逻辑专家** | 最大的开放问题。缺件/错位/交换需要部件级证据（检测 + 规格/规则图），不是又一个 patch 相似度模型。**没有它，逻辑型缺陷路由不出来。** |
| 3 | **路由器过拟合类别** | 若证据卡里塞入外观/类别强先验，路由器会退化成隐式分类器。应主要依赖专家输出统计、分歧、不确定性；必须做跨类别/跨域迁移测试。 |
| 4 | **图像级路由 ≠ 像素级定位** | 主专家分数高不代表它的 mask 对。R1 的 `R_oracle` 必须**用 mask 质量（IoU）定义 oracle**，不能只用分数。 |
| 5 | **MuSc 的 batch dependence 污染证据** | MuSc 的互评分池 = 本次请求的图。若不开固定参考池，路由器可能学到"批组成"而不是"异常类型"。**评测协议必须固定 batch 规则**（整类一次提交），或在标定/推理使用同一个固定参考池。 |
| 6 | **全部专家都错** | 必须有 `review`（§6），否则强行选一个。 |
| 7 | **路由标签来之不易** | 需要"每图哪个专家更好"的标签（由 train/val 的 GT 生成）。样本少时先停在档 A 规则路由。 |
| 8 | **多专家成本** | 全跑一遍比单模型贵。级联可缓解，但要晚于正确性验证。 |
| 9 | **参考池的定位定性** | 固定正常样本参考池（PatchCore 式 memory bank）能解决 MuSc 批次依赖，但打破"完全不使用正常样本"的前提。若项目要求零正常样本依赖，则只能接受 MuSc 的批效应，并在协议中固定 batch 组成。**两者不可兼得，必须显式选择并在论文中说明。** |

## 14. 术语

- **证据路由 / Evidence Routing**：由各专家的输出统计决定"采信哪个专家"，而非像素级加权求和。
- **Evidence Card**：路由器的输入，逐专家的分数/面积/连通域/熵/稳定性 + 两两分歧 + 上下文。
- **Reliability Router**：学习"当前证据模式下哪个专家更可靠"的模型（**不是**缺陷分类器）。
- **Oracle Router**：用 GT 事后选最优专家，作为路由上界参照。
- **弃权 / Review**：不输出结论、转人工复核的动作。
- **级联 / Cascade**：按成本顺序调用专家，灰区再升级。
- **best-single**：单专家最优基线；**混合分布**：多个缺陷族混在一起的评测分布。
